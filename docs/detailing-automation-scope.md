# REV-40. Узлы: границы автоматизации и генератор из CompoundStructure

Статус: **генератор `create_node_detail` + примитивы деталировки** (штриховка по контуру,
стили линий, дуги, разрезы, загрузка `.rfa`). Пилот 2026-07-21 закрыл ручной цикл
линиями; текущий этап — детерминированная отрисовка реального пирога стены/пола.

Подгонка под шаблон организации — когда заказчик пришлёт 1–2 своих эталонных узла
(семейства, штриховки, типы размеров/текста).

## 0. Scope: что ИИ умеет и не умеет

**ИИ не выбирает конструктивное решение**, не подбирает узел под мокрую зону/нормы,
не генерирует 3D-узлы и не заменяет проектировщика на этапе «какой узел нужен».
Без семейств и стилей организации оформление может быть технически верным, но не
«альбомом заказчика».

**Что автоматизируем** — механическое оформление, когда решение уже принято:

| Этап | Инструмент | Комментарий |
|------|------------|-------------|
| Генератор узла из пирога | **`create_node_detail`** | Читает CompoundStructure стены/пола; режимы `junction` / `single` |
| Чертёжный вид / callout / разрез | `create_detail_view` | `drafting` · `callout` · **`section`** (живой разрез по модели) |
| Эскиз слоёв / дуги / стили линий | `create_detail_lines` | `lineStyleName`, `arcs`; стили = субкатегории OST_Lines |
| Штриховка по контуру | **`create_detail_regions`** | Не `create_filled_regions` (тот — только Room на плане для нормоконтроля) |
| Подписи с выносками | `create_text_note` | Типы ADSK из проекта |
| Размеры | `create_dimensions` | Генератор ставит цепочку по точным references кривых |
| 2D-детали из библиотеки | `place_detail_component` | Линия разрыва и т.п. |
| Загрузка семейств | **`load_family`** | `.rfa` с машины Revit |
| Стили документа | `get_document_styles` | `lineStyles`, `filledRegionTypes`, `fillPatterns` |
| Лист | `create_sheet` + `place_view_on_sheet` | Или `sheetNumber` в `create_node_detail` |

**Формула для команды:**

```
Решение «какой узел» + ответственность  →  архитектор / ГИП
Эталон, .rfa, штриховки, стили линий    →  шаблон организации / библиотека заказчика
Вид, слои, штриховка, подписи, размеры  →  ИИ через MCP (create_node_detail / примитивы)
Финальная приёмка и выпуск               →  архитектор
```

**Где реальная экономия:** повтор эталонного узла на многих листах; черновик
«набросай примыкание пола М1:10» с реальными толщинами из модели; серия Уз-01…Уз-N;
живой разрез (`section`) вокруг уже смоделированного стыка.

**Не делаем в проде:** `send_code_to_revit`; генерация 3D-узлов; выдумывание конструктива
без эталона и норм.

## 1. Публичный эталон (примыкание пола к стене)

**Узел:** примыкание пола к стене / перегородке (сечение).  
**Источник:** ГОСТ 21.501, серия 2.140-1 «Примыкание полов» (зазор у стены ≥20 мм под стяжку).

Предпочтительный вызов — один тул, без ручных координат:

```json
{
  "mode": "junction",
  "wallTypeId": 12345,
  "floorTypeId": 67890,
  "scale": 10,
  "gapMm": 20,
  "name": "Узел 1. Примыкание пола к стене",
  "extraLayers": [
    { "name": "Звукоизоляция", "thicknessMm": 20, "target": "floor", "insertAt": 1 }
  ]
}
```

`wallTypeId` / `floorTypeId` — id **типа** или **экземпляра** (хендлер сам читает тип).

`extraLayers` — только **сквозные слои пирога**: каждый рисуется на всю длину сборки.
Плинтус, кромочная лента в зазоре, мастика — локальные детали, а не слои; их ставят
после генератора через `place_detail_component` / `create_detail_lines`.

## 2. Ручной сценарий примитивов (когда нужен нестандарт)

1. `create_detail_view` `{ mode: "drafting", name: "…", scale: 10 }`
2. `create_detail_lines` — контуры (+ `lineStyleName`, `arcs`)
3. `create_detail_regions` — штриховка слоёв (`fillPatternName` / `filledRegionTypeName`)
4. `create_text_note` — подписи
5. `create_dimensions` — толщины / зазор
6. `create_sheet` + `place_view_on_sheet`
7. Опционально: `load_family` → `place_detail_component`

## 3. Границы автоматизации

| | |
|---|---|
| **ИИ (MCP)** | вид, слои из модели, штриховка, тексты, размеры, лист, загрузка/размещение 2D-деталей |
| **Проектировщик** | выбор узла, эталон, приёмка по шаблону организации |
| **Вне scope** | 3D-узлы; `send_code_to_revit` в проде; полная замена архитектора на узлах |

Playbook агента: [.cursor/rules/revit-node-details.mdc](../.cursor/rules/revit-node-details.mdc).
