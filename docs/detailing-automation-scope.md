# REV-40. Узлы: границы автоматизации и чек-лист эталонов

Статус: **черновик до получения эталонов от заказчика** (критерий приёмки №1).
После согласования 1–2 узлов-эталонов документ фиксируется как границы автоматизации.

## 1. Что нужно от заказчика (чек-лист эталонов)

Для каждого из 1–2 типовых узлов:

- [ ] Файл Revit («Короткий блок» или другой) с готовым узлом-эталоном, оформленным вручную,
      либо DWG/PDF узла из выпущенного комплекта.
- [ ] Тип узла: фрагмент модели (выноска с плана/разреза) или чертёжный вид «с нуля».
- [ ] Масштаб (1:5 / 1:10 / 1:20) и уровень детализации.
- [ ] Список используемых 2D-семейств узла (детали: гидроизоляция, утеплитель, крепёж,
      профили) — имена семейств/типов или сами .rfa.
- [ ] Состав аннотаций: тексты выносок (типоразмер), марки, размерные цепочки.
- [ ] Правила размещения на листе (какой лист, рядом с чем).

## 2. Пилотный инструментарий (реализовано в этом тикете)

| Инструмент | Что делает |
|---|---|
| `create_detail_view` | Детальный вид: **callout** — фрагмент родительского плана/разреза вокруг элемента (elementId + отступ) или явной области; **drafting** — чертёжный вид с нуля. Имя, масштаб, уровень детализации. |
| `place_detail_component` | Размещение 2D-компонентов узла (точечных с поворотом и линейных) по имени семейства/типа. Если тип не найден — в ответе список доступных типов проекта. |
| `create_text_note` | Текстовая выноска: позиция в мм, типоразмер по имени, ширина переноса, прямая выноска-стрелка (leader). |
| существующие | `create_dimensions` (размерные цепочки), `get_available_family_types`, `get_document_styles`, `place_view_on_sheet` / `auto_layout_sheet` (размещение узла на листе). |

## 3. Границы автоматизации (черновая гипотеза, уточняется по эталонам)

**Делает ИИ через MCP:**
- создание детального вида нужного типа, масштаба и имени вокруг указанного элемента;
- размещение загруженных 2D-компонентов узла по координатам/правилам;
- текстовые выноски и размерные цепочки по составу эталона;
- размещение готового узла на листе.

**Остаётся вручную (или полуавтоматически, с проверкой человеком):**
- создание/загрузка самих 2D-семейств деталей (.rfa) — ИИ не рисует новые семейства;
- точная геометрия специфичной штриховки/линий, отсутствующих в семействах;
- инженерное решение узла (что именно и как примыкает) — ИИ воспроизводит эталон,
  а не проектирует узел;
- финальная визуальная приёмка соответствия нормам оформления.

**Не делаем (зафиксировано):**
- генерация 3D-геометрии для узлов;
- `send_code_to_revit` в производственных сценариях узлов.

## 4. Сценарий пилота на реальном файле

1. `get_available_family_types` / `get_document_styles` — инвентаризация 2D-семейств
   и типоразмеров текста в файле заказчика.
2. `create_detail_view` (callout вокруг элемента узла-эталона, масштаб из эталона).
3. `place_detail_component` — компоненты по составу эталона.
4. `create_text_note` + `create_dimensions` — аннотации по эталону.
5. `place_view_on_sheet` — узел на лист.
6. Сравнение с эталоном вручную → фиксация расхождений и обновление раздела 3.
