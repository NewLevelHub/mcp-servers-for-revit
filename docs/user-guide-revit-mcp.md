# Руководство проектировщика: Revit + Cursor MCP



Пошаговая настройка **без программирования**. Время — около 15 минут.



## Что понадобится



- **Autodesk Revit** 2020–2026

- **Node.js 18+** — [nodejs.org](https://nodejs.org/) (только установить, команды в терминале не нужны)

- **Cursor** — [cursor.com](https://cursor.com)

- **Шаблон проекта организации** (`.rvt`) с дверями, окнами, полами и ведомостями



---



## Быстрый старт (5 шагов)



### Шаг 1. Плагин Revit



1. Скачайте ZIP для вашей версии Revit: [Releases](https://github.com/mcp-servers-for-revit/mcp-servers-for-revit/releases).

2. Распакуйте в:

   ```

   %AppData%\Autodesk\Revit\Addins\<версия Revit>\

   ```

3. Запустите Revit → при запросе об аддине: **Always Load**.

4. Вкладка **mcp-servers-for-revit**:

   - **Revit MCP Switch** → **Open Server**

   - **Settings** → включите **все** команды → **Save**



### Шаг 2. Cursor и папка проекта



1. Скачайте или клонируйте репозиторий `mcp-servers-for-revit`.

2. В Cursor: **File → Open Folder** → выберите **корень** этой папки (где лежат `docs/`, `.cursor/`).

3. Правила агента подключатся автоматически (файл `.cursor/rules/revit-mcp.mdc`).



### Шаг 3. Подключение MCP (без сборки кода)



1. Скопируйте готовый конфиг:

   - из `.cursor/mcp.json.example`

   - в `.cursor/mcp.json`

   - замените в нём `<REPO_ROOT>` на путь к папке репозитория (через `/`,
     например `C:/dev/mcp-servers-for-revit`)

   (или выполните скрипт `scripts/setup-user.ps1` — он подставит путь сам, см. ниже)

2. Перезапустите Cursor.

3. В чате должны появиться инструменты MCP (иконка молотка).



### Шаг 4. Проверка связи



1. В Revit откройте **рабочий проект** `.rvt` (не файл семейства `.rfa`).

2. В Cursor напишите:



   > Проверь связь с Revit по правилам revit-mcp



3. В Revit появится окно приветствия. В ответе агента — таблица с `say_hello`.



### Шаг 5. Первый рабочий запрос



Скопируйте и отправьте:



> Работай только через MCP, по правилам revit-mcp. Без send_code_to_revit.  

> Покажи информацию об активном виде и сколько стен в проекте.

## Автоматическая настройка (Windows)



В PowerShell из папки репозитория:



```powershell

.\scripts\setup-user.ps1

```



Скрипт создаст `.cursor/mcp.json` из `.cursor/mcp.json.example`, подставив путь к вашему
репозиторию вместо `<REPO_ROOT>`, и выведет чеклист. Сам `.cursor/mcp.json` в git не хранится —
пути в нём машинозависимые.

## Как заставить агента следовать правилам



| Что делаете вы | Зачем |

|----------------|--------|

| Открываете в Cursor **корень** репозитория | Подтягивается `alwaysApply: true` для `revit-mcp.mdc` |

| В начале запроса пишете: **«по правилам revit-mcp, только MCP»** | Дублирует правило в контексте чата |

| Не просите «создай новый rvt файл» без шага в Revit | MCP не создаёт проект — см. ниже |

| Открываете **.rvt на шаблоне организации** | Есть типы дверей, окон, полов |



Если агент лезет в код или C#:



> Стоп. Только MCP по revit-mcp.mdc. Какие инструменты используешь?

## Готовые фразы для чата (копировать)



**Связь**

> Проверь связь с Revit по правилам revit-mcp



**Помещения**

> Выгрузи все данные помещений. Только MCP, без C#.



**Планировка**

> На Level 1 создай комнату 6×6 м: стены, пол, одна дверь, одно окно. Только create_*_element. По правилам revit-mcp.



**Перечерчивание по DWG** (REV-142, Cursor + MCP)

1. На активном плане этажа привяжите / импортируйте DWG (**лучше не explode** — оставить связь).
2. В Cursor:

> Перечерти стены по DWG на активном плане. Сначала dryRun, потом создай. По правилам revit-mcp.

Ожидаемое поведение агента:
- цепочка `get_current_view_info` → `get_cad_link_geometry` / `trace_walls_from_cad` (сначала `dryRun`, потом create);
- **не** угадывать Start/End для голого `create_line_based_element`;
- нет CAD на виде → «привяжите / импортируйте DWG», без рисования «на глаз»;
- в ответе: создано N/M, слои, **verify** (`maxDeviationMm` / failedAxes).

Подробнее: `.cursor/rules/revit-cad-redraw.mdc`.

**Двери и окна по DWG (после стен)**

> Перечерти двери и окна по DWG на активном плане. Сначала dryRun, потом создай. По правилам revit-mcp.

Ожидаемое поведение:
- стены-host уже есть → `get_available_family_types` (OST_Doors / OST_Windows) → `trace_openings_from_cad` (`category`, `doorTypeId` / `windowTypeId`, сначала `dryRun`);
- **не** угадывать `locationPoint` / `hostWallId` вручную при наличии слоёв проёмов;
- в ответе: двери N/M, окна M/K, verify maxDeviation.



**Маркировка**

> Промаркируй все помещения на активном виде. По правилам revit-mcp.



**Разделители помещений**

> Проанализируй контуры на плане (`analyze_room_boundaries`), логически поставь разделители где нужно (разрывы / open-plan), создай помещения с именами и марки. Только `analyze_room_boundaries` + `create_room_separators`, по revit-mcp.



**Материалы**

> Посчитай количества материалов. По правилам revit-mcp.



Во всех ответах агент должен перечислить **использованные MCP-функции** в конце.

## Новый файл проекта



MCP **не умеет** «Файл → Новый проект». Делайте вручную:



1. Revit → **Файл → Новый → Проект** (шаблон организации).

2. **Сохранить как** `МойПроект.rvt`.

3. В Cursor: «В открытом проекте …» + «только MCP, по revit-mcp».

## Что делает агент (и чего не делает)



| Делает через MCP | Не делает |

|------------------|-----------|

| Читает модель, создаёт стены, полы, двери, окна, помещения | Не правит код `server/`, `plugin/` без запроса |

| Выгружает данные для ведомостей | Не пишет произвольный C# (`send_code_to_revit`) без вашего согласия |

| Маркирует, красит для проверки | Не заменяет корпоративные листы и ТЭП |



**ТЭП и ведомости** — оформление в Revit по **вашему шаблону**. Агент даёт данные (`export_room_data`, `get_material_quantities`).



**Нормы (ГОСТ/СП/СН РК)** — через MCP: один раз загрузить библиотеку, потом спрашивать тему обычным языком. Подробнее — раздел ниже.

## Нормы и ГОСТы

### Что умеем

- Спросить норму обычным языком → ответ с **документом, пунктом и цитатой**.
- Один раз загрузить все PDF из папки `normatives/` в библиотеку.
- Проверить модель одним проходом: `run_norm_audit` (коридоры, глубины, лоджии/балконы, ПД) — или точечно `check_evacuation_width`, `check_fire_doors` и др.

### Чего ИИ не делает

- Не заменяет ГИП и не выдаёт юридическое заключение.
- Не выдумывает числа «из головы» — только из библиотеки/PDF с quote.
- Не требует от вас писать имена tool и пути к файлам.

### Как пользоваться (готовые фразы)

1. **Один раз:** «Загрузи все нормы из папки normatives в библиотеку».
2. **Спросить:** «Какая минимальная ширина эвакуационного коридора? Дай document, пункт и цитату».
3. **Проверить этаж:** «Проверь 1 этаж по нормам: коридоры, глубины, лоджии, ПД» → один отчёт (`run_norm_audit`).
4. **Точечно:** «Проверь только ширину эвакуационных путей на этом этаже».
5. **Статус:** «Сколько документов и правил сейчас в библиотеке норм?»

### Откуда берутся данные

- PDF лежат в `normatives/` в проекте.
- После загрузки правила — в локальной библиотеке; поиск по теме **без** указания PDF.
- В ответе всегда смотрите **document / clause / quote**.

### Чеклист самопроверки (5 минут)

1. Спросили ширину коридора → есть цитата, не «общие знания».
2. Цитата про **эвак. коридор**, а не определение «светового кармана».
3. Проверка эвакуации в Revit показывает ту же норму в отчёте.

### FAQ

| Вопрос | Ответ |
|--------|--------|
| Пустой ответ по теме | Сначала загрузите библиотеку норм; иначе документ ещё не загружен |
| Странная цитата | Попросите другой формулировкой / укажите документ |
| Нужен ли git каждому | Для работы — готовая сборка + Cursor; git нужен разработчикам |
| Почему иногда пропадают tools норм | В `.cursor/mcp.json` укажите system Node (`C:/Program Files/nodejs/node.exe`), не bundled Node Cursor |

## Устранение неполадок



### Чеклист связи Cursor ↔ Revit (перед длинной сессией)



1. Revit открыт с **одним** рабочим `.rvt` (не семейство `.rfa`).

2. Вкладка **mcp-servers-for-revit** → **Revit MCP Switch** → **Open Server**.

3. На ribbon статус: **Connected** (сервер слушает). После обрыва Cursor покажет **Reconnecting**, пока канал не восстановится; **Offline** = сервер выключен.

4. **Settings** → нужные команды включены → **Save**.

5. В Cursor MCP-сервер `mcp-server-for-revit` активен (зелёный). При сомнении: перезапуск Cursor **не** обязателен — плагин и Node-сервер сами переподключаются (heartbeat ~10 с, backoff ≤ 15 с).

6. Быстрая проверка: попросите агента вызвать `say_hello`. Если ошибка про Open Server — вернитесь к шагу 2.



| Симптом | Действие |

|---------|----------|

| Нет инструментов MCP | Скопируйте `mcp.json.example` → `mcp.json`, перезапустите Cursor |

| Ошибка при вызове tool | Revit → Settings → включите команду; проверьте **Open Server** |

| «Сервер MCP в Revit выключен» | Ribbon **Offline** → нажмите **Open Server** |

| «Связь с Revit потеряна» / Reconnecting | Подождите ≤ 15 с; если не восстановилось — Restart Open Server и повторите команду |

| «Команда превысила N с» | Канал жив; повторите тяжёлую команду или разбейте задачу — timeout одной команды не рвёт соединение |

| «Нет стен / дверей» | Открыт `.rfa` вместо `.rvt` — откройте проект на шаблоне |

| Агент правит код репозитория | «Работай только через MCP, по правилам revit-mcp» |

| Агент использует C# | «Без send_code_to_revit» или явно: «разрешаю C#» |
