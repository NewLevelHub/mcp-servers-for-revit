# Сбор отзывов от архитекторов

Как жалоба из чата в Revit доезжает до разработчика.

## Что видит архитектор

Под каждым ответом ассистента есть 👍 👎. По 👎 открывается форма:

- тег причины (не понял запрос / не тот инструмент / сломал модель / выдумал нормы / не довёл до конца / слишком долго / ошибка-упал);
- поле комментария;
- кнопка **📷 Приложить скрин** — снимает окно Revit целиком, вместе с чертежом и открытой панелью чата;
- **Отправить**.

Достаточно чего-то одного: тега, комментария или скриншота. После отправки под ответом появляется «Записано» — или «Не сохранено», если запись в лог не прошла.

## Что происходит дальше

1. Жалоба ложится строкой в `Logs/assistant-sessions_{дата}.jsonl` рядом с самим ходом (запрос, ответ, цепочка инструментов, тайминги, ошибка).
2. Скриншот сохраняется в `Logs/feedback-shots/` и живёт 30 дней.
3. Панель сама собирает накопленные жалобы в архив `Logs/Feedback/feedback_{автор}_{компьютер}_{дата-время}.zip`:
   - `report.md` — читаемый отчёт, сгруппированный по тегам, со ссылками на скриншоты;
   - `raw.jsonl` — те же жалобы вместе с полным ходом, для машинного разбора;
   - `shots/*.png` — приложенные снимки.
4. Архив копируется в **общую папку**, если она задана.

Уже выгруженные жалобы помечаются, поэтому повторный сбор их не дублирует. Если общая папка была недоступна (VPN, выключенный сервер), архив остаётся на компьютере и уедет при следующем открытии панели — копирование идемпотентно по имени файла.

Сборка запускается автоматически при открытии панели и после каждой жалобы, **только когда задана общая папка**. Без неё архивы не собираются молча: в шапке панели горит счётчик `📊 N`, по нажатию собирается архив и путь копируется в буфер обмена.

## Настройка на компьютере архитектора

Revit → лента → Настройки → Ассистент → блок **Сбор отзывов**:

| Поле | Что вписать |
|---|---|
| Кто пользуется (ФИО) | `Иванов И.` — подпись на архиве. Пусто → имя пользователя Windows |
| Общая папка для жалоб | Куда складывать архивы |

Что годится в качестве общей папки:

- сетевая шара в офисе — `\\server\share\revit-ai-feedback` (проще всего, если все в одной сети);
- папка облачного диска — `C:\Users\ivanov\YandexDisk\revit-ai-feedback`, расшаренная на разработчика (работает и вне офиса);
- любой примонтированный диск.

Права нужны только на запись — архитектор не читает чужие жалобы.

## Как разработчику разобрать поток

Архивы копятся в общей папке; имя файла сразу говорит, кто и когда жаловался. Внутри `report.md` читается глазами, `raw.jsonl` скармливается модели вместе со скриншотами.

В шапке `report.md` и в поле `build` каждой записи стоит версия сборки — по ней видно, баг это или машина, до которой исправление ещё не доехало. Как исправление доезжает: [auto-update.md](auto-update.md).

Гит для этого не нужен и не годится: у архитектора нет ни репозитория, ни доступа на push, а жалобы со скриншотами в истории кода — мусор, который потом не вычистить.

## Если общей папки нет

Архивы лежат в `%AppData%\Autodesk\Revit\Addins\{версия}\revit_mcp_plugin\Logs\Feedback\`. Забрать их можно как угодно — AnyDesk, почта, мессенджер. Кнопка `📊 N` в шапке панели собирает всё накопленное в один архив и кладёт путь в буфер обмена.

## Смежное

- `Authentication error. If you are logged in, try logging out and back in.` — Cursor отклонил запрос, чаще всего у долго живущего процесса движка. Настройки → Ассистент → **Перезапустить движок**; Revit закрывать не нужно.
- Логи движка: `Logs/assistant-bridge_{дата}.log` — единственное место, где видно, что именно ответил Cursor.
